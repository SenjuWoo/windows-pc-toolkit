## Shared dashboard/core defects repaired

- Registry equality ignored case, skipping case-only writes and losing conflict detection. Compare literal serialized values case-sensitively.
- Preview omitted reviewed startup/app choices; Optimize refused reviewed-only runs. Include those selections and freeze profile controls during operations.
- Worker import/JSON failures escaped before the result handler, while partial failures dropped their report. Return a visible failure envelope and retain reports/causes.
- Recovery trusted JSON-supplied report paths, displayed foreign-computer reports, and claimed success for repair/cache-only undo. Use the actual local report path and reject nonreversible journals.
- Existing linked state directories could redirect writes. Check existing ancestors before state/package reads and writes. App reinstall now checks persisted file hashes, containment and all linked descendants before registration.
- Task lookup could expand wildcards to unrelated tasks. Filter exact task identity and pass the resulting CIM object to enable/disable. Already-disabled tasks are skipped.
- Shared registry care used a stale missing-executable scan. Recheck the current command before removal so replacements survive review.
- Recall undo rejected the ordinary Disabled state following a DisablePending reboot. Record the expected completed state and support older pending-state journals.
- Restore-point creation assumed success from a no-output command. Treat warnings as failures and require a new matching restore-point sequence number.
- DISM repair lacked explicit `/NoRestart` and continued after restart-required completion. Defer remaining repair commands until Windows restarts.
- Root launcher lost the child exit status; standalone launchers had path/UAC/service-check defects. Preserve exit codes and originating user identity for HKCU-changing consoles. Alternate administrator credentials abort before bootstrap.
- Add bounded diagnostics with version, configuration, run/action and failure cause. Debug defaults off; operation reports retain normal results.

Quad9 Secure secondary IPv6 is `2620:fe::9`, as verified against [Quad9's current service table](https://docs.quad9.net/services/). The prior `2620:fe::fe:9` assertion was wrong. DNS writes now require supported typed Windows DoH cmdlets instead of interpreting localized netsh text. [Microsoft DoH controls](https://techcommunity.microsoft.com/blog/networkingblog/windows-insiders-gain-new-dns-over-https-controls/2494644), [scheduled-task wildcard contract](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/get-scheduledtask), [restore-point behavior](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/checkpoint-computer?view=powershell-5.1).

## Evidence and limits

Run `tests/Test_All.ps1` in Windows PowerShell 5.1 STA; CI runs it in canonical and installed friendly layouts. Checks use real disposable HKCU/files/junctions, native CMD/PowerShell processes, actual WPF/jobs/timer, read-only Windows inventories, real stay-awake/SFC-help and native-process fixtures. Mutation commands for DNS, servicing, packages, services, storage and restore points are intercepted. Launcher targets are harmless marker scripts; the fixture substitutes the principal gate when the host token is not administrative, so interactive UAC acceptance is not proven.

See [validation evidence](../VALIDATION_REPORT.md) and the exact commit's CI checks. This audit does not certify every Windows build, live corruption repair, AppX re-registration, provider connectivity or gaming performance. No live optimizer/debloat/DNS/repair action was applied to the host. Cleanup can race external filesystem changes; locked/inaccessible files are skipped. Old console snapshots require review and may replace later manual changes. Older AppX backups without hashes use Store reinstall rather than automatic registration. These are documented limits, not a claim that the app is perfect.
