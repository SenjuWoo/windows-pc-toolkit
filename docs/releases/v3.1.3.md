# Windows PC Toolkit 3.1.3

Safety release for the legacy optimizer repair, the OneDrive folder gate and encrypted DNS. Extract the complete **Windows-PC-Toolkit-3.1.3.zip** into a new folder and run **START_TOOLKIT.bat**; close older dashboards first. Existing reports and backups in `%ProgramData%\WindowsPCToolkit` remain available.

- The opt-in cleanup for v3.x leftovers no longer forces SysMain to Automatic or turns on RSS/RSC for each adapter. It removes the overrides it can identify, prints the current SysMain state and leaves adapter offloads at the driver setting, because the value from before the old tweak was never recorded. The MMCSS Games values are written only when they differ from Microsoft's documented defaults, and the snapshot taken before the change still restores a custom configuration through undo.
- The OneDrive gate now treats a missing Explorer `Shell Folders` cache entry as unverified instead of assuming the folder is local. The lock and uninstall actions stay blocked until Explorer has written that cache; nothing rewrites folder paths.
- Encrypted DNS hands back the exact snapshot it created and the dashboard records that path for undo, rather than whatever snapshot happened to be newest. Standalone DNS changes take the same operation mutex as the dashboard, so a console and the dashboard cannot mutate DNS at once. A refused operation writes nothing.

Hosted RSS/RSC and SysMain settings a user set deliberately are now preserved by the repair; the automatic gaming profile already behaved that way. The [OneDrive folder preflight](https://github.com/SenjuWoo/windows-pc-toolkit/blob/v3.1.3/docs/ONEDRIVE_RECOVERY.md) and the earlier safety bounds are unchanged.

[Validation and runtime limits](https://github.com/SenjuWoo/windows-pc-toolkit/blob/v3.1.3/VALIDATION_REPORT.md). Fixture checks do not prove a live OneDrive migration, uninstall, Windows repair or performance improvement. Exact release commit, CI links and hashes are attached in **release-provenance.json** and **SHA256SUMS.txt**.

Diagnostics: `%LOCALAPPDATA%\WindowsPCToolkit\Logs`. Detailed logging: `-DebugLog` or `WINDOWS_PC_TOOLKIT_DEBUG=1`.
