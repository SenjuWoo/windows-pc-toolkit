# Windows PC Toolkit 3.2.0

PC Cleaner 1.2.0 adds a Cache Explorer for AI, gaming and developer caches. Extract the complete **Windows-PC-Toolkit-3.2.0.zip** into a new folder and run **START_TOOLKIT.bat**; close older dashboards first. Existing reports and backups in `%ProgramData%\WindowsPCToolkit` remain available.

- Menu `[8]` scans caches read-only, grouped by AI, Gaming and Dev. Every row shows its size, newest file, risk and whether it is deletable; a JSON report can be exported.
- Deletable after a typed confirmation: Antigravity editor caches (only when its `User` folder proves the layout), Steam `shadercache` and staging temp in every library found through `libraryfolders.vdf` with Steam closed, VRChat `Cache-WindowsPlayer`, Epic webcache folders with the launcher closed, Roblox and Minecraft logs older than seven days, pip/npm/NuGet download caches, and Unreal DDC or Gradle caches as STRICT choices with their rebuild cost printed.
- Report-only: the Codex, Claude and Hermes homes and Unity project libraries. Sessions, archived sessions, SQLite state, `.claude.json`, memories, skills, plugins, credentials, `tmp\arg0`, `state.db` and model stores are never in scope.
- The scan is bounded at 50,000 files per category, so a large library cannot freeze the console. Cleanup reports bytes actually removed plus skipped and locked files; scan sizes are estimates.

The existing cleaner engine still makes every decision: protected names, reparse points in any parent, protected or linked items inside a directory and locked files all skip. Four gates were added: a report-only category refuses deletion, a required signature folder must exist, a running application blocks its category, and a cache root holding a protected folder is refused whole instead of half-emptied.

Cache deletion is irreversible and may require a rebuild or re-download. The toolkit does not quarantine caches: a copy on the same drive would not reclaim space.

[Validation and runtime limits](https://github.com/SenjuWoo/windows-pc-toolkit/blob/v3.2.0/VALIDATION_REPORT.md). 30 new fixture checks run against disposable TEMP folders; no real cache, game, project or user folder was read or changed. Fixture checks do not prove a live cleanup. Exact release commit, CI links and hashes are attached in **release-provenance.json** and **SHA256SUMS.txt**.

Diagnostics: `%LOCALAPPDATA%\WindowsPCToolkit\Logs`. Detailed logging: `-DebugLog` or `WINDOWS_PC_TOOLKIT_DEBUG=1`.
