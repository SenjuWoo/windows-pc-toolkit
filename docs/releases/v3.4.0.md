# Windows PC Toolkit 3.4.0

PC Cleaner 1.4.0: deletion-safety hardening for custom cache roots, execution-time revalidation of every Skyrim/modding target, and broader verified coverage. Extract the complete **Windows-PC-Toolkit-3.4.0.zip** into a new folder and run **START_TOOLKIT.bat**; close older dashboards first.

## Deletion safety

- **One cleanup-root validator** decides what may be a cache root at all: no drive roots, no Windows/Program Files/ProgramData, no profile, AppData or LocalLow root, no Documents/Desktop/Downloads/Pictures/Videos/Music, no game library or cloud-sync folder, and nothing that contains one of those as a descendant. A custom root must also be named as a cache.
- **VRChat `cache_directory`** is honoured but only deletable when it passes that validator. A malformed value such as `C:\` is measured and kept, never replaced by another location. The path is re-read at execution time, so a config that changed after the scan is refused with "rescan" instead of being followed.
- **Every container target** — catalog or custom — passes the link, reserved-location and containment checks immediately before deletion. A junction is never traversed; a refusal marks the row skipped with the reason.
- **Skyrim and modding cleanup re-derives everything at execution time**: processes, the Documents known folder, cloud-sync state, the approved target list and the exact folder. A stale or forged scan row can no longer authorize a deletion, and a row whose folder moved is refused.
- Empty-directory pruning is capped and never follows a link.

## Coverage

- **Modding tools** are a real category now, not a note: Mod Organizer 2 `logs` (`mo_interface*.log`, `usvfs-*.log`), Vortex `vortex*.log`, and DynDOLOD/TexGen/LODGen `*_log.txt`. Only those names are eligible; mods, profiles, overwrite, downloads, Vortex state and generated LOD output stay. A portable MO2 or DynDOLOD install is listed only when its folder is passed in (menu `[5]`) — no drive is ever searched.
- **New cache categories**: Yarn cache (SAFE), pnpm store (REPORT — hard-linked into projects, `pnpm store prune` is the right tool), GPU driver shader caches (`NVIDIA\DXCache`, `NVIDIA\GLCache`, `AMD\DxCache`) and DirectX `D3DSCache` (both STRICT and opt-in, because recompilation causes first-launch stutter).
- Catalog is 20 categories: 13 deletable, 7 report-only.

## Corrected documentation

`pc-cleaner/README.md` said Steam staging and Epic webcache were cleanable; both are report-only in the catalog and now say so. The cleaner's header version matches the shipped version again.

## Limits

No live cache, game or modding log was deleted while validating; every check ran on disposable TEMP fixtures. MO2/Vortex/DynDOLOD detection relies on their documented default folders — a portable install appears only when you point at it. Sizes are estimates, there is no undo, and no shader recompilation or FPS effect was measured.

[Validation and runtime limits](https://github.com/SenjuWoo/windows-pc-toolkit/blob/v3.4.0/VALIDATION_REPORT.md). Exact release commit, CI links and hashes are in **release-provenance.json** and **SHA256SUMS.txt**.

Diagnostics: `%LOCALAPPDATA%\WindowsPCToolkit\Logs`. Detailed logging: `-DebugLog` or `WINDOWS_PC_TOOLKIT_DEBUG=1`.
