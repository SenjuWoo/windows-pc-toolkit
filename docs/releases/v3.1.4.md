# Windows PC Toolkit 3.1.4

Correctness fix for the opt-in cleanup of v3.x leftovers. Extract the complete **Windows-PC-Toolkit-3.1.4.zip** into a new folder and run **START_TOOLKIT.bat**; close older dashboards first. Existing reports and backups in `%ProgramData%\WindowsPCToolkit` remain available.

- 3.1.3 tried to leave MMCSS Games values alone when they already matched a default. That check could never run: the same cleanup deleted those six values first, so every repair rewrote all of them from a hardcoded guess. The repair now journals the block, skips it in the deletion loop and does not write it at all. Microsoft documents the value ranges, not one shipping default, and the defaults differ between Windows builds and OEM images.
- Self-configured values are therefore preserved: a custom GPU Priority, a non-default Scheduling Category, a non-default Background Only or a custom Clock Rate survive the repair, and a missing value stays missing instead of being invented.
- The other legacy targets (NTFS/cache overrides, storage LPM, Dnscache TTL, QoS NLA, NetworkThrottlingIndex, SystemResponsiveness, BCD timer flags) are still removed after the snapshot, so undo restores them.
- The OneDrive cache check, the DNS snapshot identity and locking, and the SysMain/offload preservation added in 3.1.3 are unchanged.

The [OneDrive folder preflight](https://github.com/SenjuWoo/windows-pc-toolkit/blob/v3.1.4/docs/ONEDRIVE_RECOVERY.md) and the earlier safety bounds are unchanged.

[Validation and runtime limits](https://github.com/SenjuWoo/windows-pc-toolkit/blob/v3.1.4/VALIDATION_REPORT.md). The new regressions run the actual snapshot-then-delete order against a disposable HKCU fixture and were confirmed to fail on the 3.1.3 implementation. Fixture checks do not prove a live repair. Exact release commit, CI links and hashes are attached in **release-provenance.json** and **SHA256SUMS.txt**.

Diagnostics: `%LOCALAPPDATA%\WindowsPCToolkit\Logs`. Detailed logging: `-DebugLog` or `WINDOWS_PC_TOOLKIT_DEBUG=1`.
