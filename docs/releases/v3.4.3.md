# Windows PC Toolkit 3.4.3

PC Cleaner 1.4.3: a cache path that turns into a regular file is refused instead of being deleted as a stray file, and the README download links now follow the release they advertise. Extract the complete **Windows-PC-Toolkit-3.4.3.zip** into a new folder and run **START_TOOLKIT.bat**; close older dashboards first.

## A cache that becomes a file is no longer deleted

`Resolve-CacheTargets` decides per path whether it is a folder or a file. A catalog path that was a cache directory at scan time and is a regular file by clean time used to fall into the plain-file branch, where it was deleted with none of the cache-root checks applied. On Steam shader caches that meant the one path the policy exists to police could skip the policy entirely.

- A literal catalog path is now recorded as a folder expectation. If the path is a file when the clean runs, the row skips it with "Expected a cache folder, found a file" and the file survives, untouched.
- Root-policy validation runs before the file/folder split, so a cache root cannot bypass validation by changing type.
- Wildcard rows are unaffected: a pattern such as `*.log` still matches and deletes the files it names, because that is a real file pattern rather than a cache root.
- Measurement follows the same rule, so a file sitting where a cache folded was is not counted as reclaimable.

Regression test: two scanned shader caches, the second replaced by a regular file between scan and clean. The valid cache is cleaned, the replacement file survives with its contents intact, the scan reports zero eligible bytes for it, and a wildcard log row still deletes its matched file.

## Documentation

`README.md` advertised "Download v3.4.2" while its links still pointed at v3.4.0. All download and release-notes URLs now name the shipped version, and `Validate_All.ps1` fails the build when any README link or ZIP name disagrees with `SuiteVersion`.

## Limits

Fixtures only; no live cache, game or AI state was deleted. The type check relies on the path itself, so a mount point that changes type between scan and clean is caught by the same rule, but a filesystem that reports a folder as a file mid-operation is outside what the tests can reproduce. Sizes are estimates; there is no undo.

[Validation and runtime limits](https://github.com/SenjuWoo/windows-pc-toolkit/blob/v3.4.3/VALIDATION_REPORT.md). Exact release commit, CI links and hashes are in **release-provenance.json** and **SHA256SUMS.txt**.

Diagnostics: `%LOCALAPPDATA%\WindowsPCToolkit\Logs`. Detailed logging: `-DebugLog` or `WINDOWS_PC_TOOLKIT_DEBUG=1`.
