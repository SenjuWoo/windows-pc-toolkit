## Reproduced defects and corrections

- Suite undo accepted same-identity journals with unsupported registry/feature targets. It now validates the complete journal before changes, restricts targets to supported catalogs and limits optional-feature restore to Recall.
- AppX restore compared inventory counts but accepted a duplicated hash record in place of an unchecked manifest. Inventory paths must now be unique and exactly cover the copied files.
- An existing Suite state directory could retain broad write permissions. Initialization now validates existing directories as well as protecting new ones, refusing unsafe ownership/permissions rather than trusting previously writable data. Worker requests receive the same checks.
- Privacy recovery accepted arbitrary registry, service and task targets and could restore early records before rejecting a later malformed value. All records and required inventories are validated before writes.
- Gaming recovery could restore registry settings before discovering a malformed value, unavailable adapter or invalid boot setting. Complete typed preflight and read-only availability checks now precede changes; snapshot filenames are unique and state paths reject links.
- A legitimate disabled-but-running service could not be restored by setting Disabled before starting it. Recovery starts it through Manual, then restores Disabled, and avoids forcing uncaptured dependent services to stop.
- A schema-4 DNS snapshot missing `Automatic` could enter the legacy branch and silently reset static DNS. Modern schemas require their mode/family fields; encryption records and declared touched addresses are validated together before mutation. Historical provider backups remain supported.
- Fixer thumbnail/icon cleanup followed linked Explorer cache paths. Root, ancestor and file links are refused; literal filenames and skipped/restart errors remain visible in results.
- Fixer AI/DNS backup failures could be nonterminating, allowing mutations without a saved recovery file. Both writers now stage and verify complete JSON before publishing a unique snapshot; failed saves stop the operation.
- Fixer restore-point creation could report success after a warning or no-op. Success now requires a newly observed sequence with the requested description.
- Privacy used an obsolete Edge telemetry policy. It now uses the supported [DiagnosticData policy](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/diagnosticdata); Windows diagnostic-data policy remains a separate explicit choice.
- The cleaner's unused legacy file/whole-key manifest restore could write arbitrary locations without current journal safeguards. Automatic legacy recovery is retired; old backup files are preserved and their folder is displayed for manual review. Current typed registry-care undo remains supported.
- A read-only capture of the real Windows DNS state exposed trailing NUL padding in native registry `NameServer` strings. The shared reader now strips terminator padding before capturing addresses. DNS/Fixer recovery normalizes that known padding in historical address arrays before strict validation; embedded NUL corruption remains refused. The native capture then passed with adapter DNS and DoH configuration unchanged.

The fixtures reproduce these failures using disposable registry values/files, real junctions and intercepted Windows mutation commands. [VALIDATION_REPORT.md](../VALIDATION_REPORT.md) records the final gates and their limits; release provenance identifies the exact published commit and archive.

## Safety boundaries

No live optimization, debloat, DNS change, Windows repair, servicing or app removal is performed to validate the audit. The tests exercise command orchestration and failure paths; they do not certify live provider reachability, every Windows edition/build, interactive UAC, AppX/Recall outcomes or FPS gains.

Run one component operation at a time. The dashboard serializes its mutations, but standalone consoles have independent snapshots. Identical or sequential writes across components cannot establish which later operation owns a setting. Advanced restores therefore retain an explicit warning and confirmation that they can replace subsequent settings; this pass does not add a new shared transaction system.

Temporary/cache deletion and removed app data are not reversible through registry/package journals. Damaged backups are refused rather than partially interpreted. Administrator software can still fail because of native permissions, policy, dependencies, servicing or external changes between validation and execution; failures must remain visible in logs and reports. No claim of perfection or universal safety is made.
